# 工作流检查与选择

## 使用路径

- 镜头右侧的“模型”只列出已加入工作流列表、且当前检查允许执行的选项。
- “管理模型与工作流”打开完整管理面板。“我的工作流”用于日常选择；“可添加”包含尚未加入或已从列表移除的工作流。内置模板仍须主动添加。
- 不可用的工作流可以打开检查，但不能绑定或生成。已有镜头保留原工作流，检查失败不会悄悄切换模型。
- “解决问题”显示影响使用的原因，提供重新检查、打开对应 ComfyUI 工作流、下载 JSON 等操作。未安装 TakeBoard ComfyUI 桥接扩展时，可以将下载的 JSON 拖入 ComfyUI。
- 归档仍是可恢复的文件管理操作，不是可用性状态；项目引用检查仍然有效。

## 三种状态

| 状态 | 含义 |
| --- | --- |
| 可用 | 当前检查允许执行；非阻断的源文件提醒不影响选择 |
| 需要更新 | 输入设置未完成、绑定过期或模板输入与节点不兼容 |
| 不可用 | 缺少依赖、无法读取，或尚未得到可执行的检查结果 |

检查结果不等于生成质量保证，也不能预先保证显存、第三方节点的运行时行为或网络稳定。生成时仍会检查实际提交的 Prompt，不跳过服务端校验。内置适配器与源画布仍有不同执行方式，不能将源画布检查冒充为 GPU 实测。

## 兼容处理边界

### TakeBoard 推荐模板

“可添加 → TakeBoard 推荐”提供 9 份配置：MiniMax H3 文生视频、图生视频、多素材参考，Qwen Image 文生图、图生图，Wan 2.2 图生视频和首尾帧的质量版、预览版。LTX 暂未纳入内置下载目录，其旧适配器仍保留兼容。

- 推荐 JSON、兼容性检查与实际生成共用原生 Prompt 构建器，避免检查旧画布却执行另一套节点的误判。能力来自明确的模板目录；完整模型清单来自实际执行图，并核对相应加载节点提供的模型选项。
- 打开目录会只读检查当前生成设备；点击“添加模板”后重新确认设备、依赖与内容，将模板写入该设备的 ComfyUI 工作流目录，并加入“我的工作流”。不自动选中模型或改变现有镜头。
- 模板文件随应用提供，不必另外寻找 JSON。也可单独下载 JSON；媒体输入是占位文件，需要在 TakeBoard 连入素材，或在 ComfyUI 中选择自己的素材后运行。
- 内容哈希构成独立版本路径，写入使用 `overwrite=false` 并读回校验。已有文件被修改时拒绝覆盖；中断后重新检查，可继续加入已写入的相同文件，不重复建文件。列表里的自定义名称、收藏保持不变。
- 文件版本不是旧执行引擎的快照：升级 TakeBoard 后，内置模板由当前版本构建器执行并重新检查。旧文件和镜头引用保留；要固定并修改节点图，请创建可编辑副本并完成绑定。
- 不自动下载模型权重、安装第三方 Python 节点或重启 ComfyUI。这些涉及体积、许可与代码执行；缺失依赖会阻止添加，提供所需文件/组件清单和配置说明。

TakeBoard 推荐模板的兼容维护由项目负责，不要求用户去修正内部必需字段；不过不同 ComfyUI / 自定义节点版本仍可能不兼容，不能据此承诺在任意设备上无条件运行。

2026-09-14 对当前 ComfyUI `/object_info` 的只读核对中，9 份配置的必需输入、连线来源和对应模型选项均通过。未提交生成任务；此记录不是 Windows/Mac、显存容量或视频质量的实测证明。

### 用户导入的工作流

模板检查与最终提交共用 `inspectPromptInputs`：动态输入 `values.image1` 等不再被误报为缺少 `values`；按 Autogrow 模板的最小输入数、具名/前缀输入与可选组处理，允许明确声明零输入的组，不用点号字段绕过普通必填项。指向不存在节点的连线仍会阻断自定义工作流。[ComfyUI V3 输入规则](https://docs.comfy.org/custom-nodes/v3_migration)

UI 工作流转换可以恢复具名控件值，并补齐当前节点定义中明确提供的安全标量默认值（合法数字、布尔值、枚举）。没有默认值、不在范围内的默认值、模型或文件路径、自由文本、强制连接与断线不会自动补齐。若还有无法对应的旧控件值，也不会用默认值掩盖歧义。已经存在的选择保持不变；直接导入的 API Prompt 不走 UI 默认值兼容处理。

转换只作用于执行副本，不写回工作流，不更换模型、不安装第三方代码，也不绕过内容哈希和显式信任确认。未能确认根因时不会武断地称为“模板过旧”。技术详情保留原始诊断供排查。

- `packages/executor-comfy/test/native-catalog.test.ts`：对照独立记录的节点必填项检查 9 份推荐配置。
- `apps/server/test/workflow-templates.test.ts`：目录与真实路由集成、依赖阻断、设备变更、文件冲突、写入回读、失败恢复与幂等添加。

- `apps/server/test/workflow-diagnostics.test.ts`：缺失依赖与执行条件。
- `apps/web/src/workflow-library.test.ts`：非阻断提醒、不可用及需要更新状态。
- `e2e/workflow-readiness.spec.ts`：模型过滤、友好诊断、原始信息按需展开、编辑入口、重新检查后才能选择，以及多窗口尺寸。
- `e2e/recommended-templates.spec.ts`：主动添加、离线下载入口、依赖阻断、筛选、重新检查、添加后镜头不变，以及响应式布局。

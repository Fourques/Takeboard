# 全项目删减审计

日期：2026-09-10。范围包含现有工作区子项目、核心创作链路、可选能力、桌面与远程运行、发行脚本及当前文档，而非仅上一轮连接改动。

这是基于调用关系、实现边界与回归测试的产品/架构审计，不声称逐行证明全仓库没有缺陷，也不代替新安装包或真实模型验收。

## 第一性目标

用户需要把自己的素材、工作流、生成结果和选择记录放在一个可理解、可恢复的项目中。
TakeBoard 的价值是创作过程和文件归属清晰，而不是功能、服务或框架越多越好。

由此得到四条判断：

- 不需要账号、门户或多设备调度，也应能完成本机创作。
- 项目在哪，与 GPU 在哪是两个独立选择；换生成设备不该刷新或迁移项目。
- 重复实现同一规则，比适当的模块边界更危险。
- 权限、恢复、校验和操作来源有实际损失防护价值，不能按代码行数评价其冗余。

## 已简化

- 工作区从 12 个（含根项目）减为 10 个，不再为无消费者的包单独构建和维护版本。
- 桌面预览工作流改名 `desktop-preview.yml`，源码启动器改名 `runtime-launcher.mjs`；安装包内仍保留 `launcher.mjs`，不破坏远程启动协议。相关测试、触发路径与当前文档同步更新。
- 项目目录加载与生成环境发现分开。ComfyUI 慢或离线时，已有项目仍能载入；切换生成服务只更新生成环境，不重读项目与回收站。
- 连接成功只通过一个变更事件触发环境更新，删掉面板额外回调造成的重复刷新。
- 顶栏面板首先说明当前服务状态，多设备列表收起。连接并使用与注册额外调度设备明确区分。
- 删除用途标签对画质的暗示：预览/日常/终稿只是管理员声明的用途，不是模型实测或质量保证。

## 检查后保留的能力

| 范围 | 为什么不是冗余 | 约束 |
| --- | --- | --- |
| 首页 3D、画布和分镜墙 | 首页形象、自由创作与顺序审片是不同任务；用户已明确选择原有首页设计 | 不以重做视觉风格代替简化流程 |
| 原始素材、代理、生成归档 | 原件完整性、显示性能和结果归属不同，不能简单合并为一个文件 | 不动原件，不默删远端输出 |
| 命令预览、确认、撤销、记录 | 替换/删除/并发操作会产生真实损失 | 不能删除校验只留下“撤销”按钮 |
| 服务端对账与前端状态查询 | 前者保证关页面后仍能收集结果，后者负责可见状态 | 不把生成恢复依赖于浏览器是否打开 |
| 下载临时文件、完整性校验与重试 | 网络/磁盘失败不能把半个视频标成完成，也不能无故重新耗费 GPU | 完整文件重试，不宣称断点续传 |
| 账号、项目权限与 Portal | 本地项目访问权与门户设备配对是不同信任边界 | 登录附加；不把“同账号”当作自动授权；未配对不启动中继 |
| 成本、批量审片、粗剪与质检扩展 | 已有明确使用场景与测试，不应为缩代码而剥夺选择 | 继续默认关闭，不另造任意代码插件框架 |
| 多设备策略 | 显式隐私、预算约束与选择理由对真实多设备用户有用 | 不作为基础生成必填项；不承诺自动提高画质或省钱 |
| 备份、恢复与演练 | 项目包和实例备份的恢复范围不同，账号/权限恢复不是素材导出的重复 | 定时备份须显式配置；不自动新增计划 |
| Web、桌面、Server、可选 Portal | UI、原生能力、项目数据和中继各有边界，桌面复用同一业务服务 | 不合并成会同时公开文件系统与中继权限的进程 |
| Demo 与测试模拟生成 | 无 GPU 时演示与可重复测试仍需要独立夹具 | 不冒充真实模型生成或兼容性证据 |

## 初次审计时的真实债务

本节保留最初判断，后续实施结果见文末；其中旧接口与模块提取已继续处理，不能再作为当前未完成清单。

- `App.tsx` 接近 6,000 行，职责确实集中。但机械拆文件不会自动减少状态耦合。本次先删除已证实的目录/生成耦合，不同时重写所有创作交互。
- `project-routes.ts` 仍保留 11 个旧画布/镜头写接口，与命令服务有重叠。再次核对本地发布标签发现，`v0.1.0`、`v0.2.0-beta.1`、`beta.2`、`beta.3` 的 Web API 均已使用命令服务；可明确证明仍调用旧接口的是部分服务端测试和浏览器测试准备逻辑。此前把“旧客户端兼容”作为保留整套实现的理由不够严谨。没有外部调用统计，不能断言所有第三方都已迁移，但也不应因此无限期维护两套规则。
- 原生模型适配与通用工作流绑定并存。前者负责已有内置预设，后者执行用户真实工作流；在所有内置预设迁移并验证前，不盲目删除任一执行路径。
- 最新远程生成的连接记录与 Worker 注册表仍分开存储。没有在这次删减里引入配置迁移或第三个统一注册框架；失败路径与身份一致性仍需持续回归。

## 初次删减验证口径

本轮 `pnpm verify` 通过，包含 319 项单元/集成/脚本测试；35 项浏览器测试全部通过。新增针对性检查覆盖慢工作流发现不阻塞项目显示、切换生成服务不重新读取项目目录。删除旧 Recipe 包时同时移除了只验证该废弃实现的两个测试，不以删减测试掩盖现有业务失败。

Linux x64 的 `pnpm desktop:prepare` 与包内运行时检查通过：真实启动、远程 helper 复用端口、重启后项目默认位置及会话保留、自有租约释放。启动器路径变更未破坏安装包内协议；这不等于已发布新安装器。Mac / Windows 新版原生窗口和真实 GPU 生成仍按各自发布门槛验收。

## 删减清单复核与后续顺序

Git 当前列出的 13 个删除路径中，**10 个实际删除，3 个只是改名**：

- 实际删除：旧 Recipe 包 4 个文件、占位测试包 3 个文件、便携构建/个人部署/个人截图脚本各 1 个。
- 改名：预览工作流、运行时启动器、运行时实例发现测试。预览工作流改名前后内容哈希完全一致，不能算作删除发行能力。
- 根目录便携构建命令、锁文件中两个废弃 workspace 入口已移除；新启动器路径已同步到打包脚本、测试和 CI 路径过滤。
- 当前代码与工作流中未找到残留的旧文件调用。审计中的历史路径只用于说明删减对象，不是可用入口。
- 这里只核实源码仓库；不据此断言用户外部脚本没有调用过旧个人脚本，也没有清理忽略目录或线上附件。

旧接口存在的差异已经不只是重名：旧复制接口只创建引用同一对象的画布节点，新命令对镜头/笔记创建独立对象；旧连线替换没有命令预览确认和可撤销记录，新命令会要求确认；旧按端点删除连线还有“目标只剩一条线时猜测匹配”的回退。它们仍受认证与项目锁保护，但不具备相同的操作语义。

建议实施顺序：

1. 为 11 个入口建立行为对照和回归用例，保留测试意图，将测试准备逻辑迁移到命令 API。
2. 删除旧独立写实现。已确认不再使用的接口可在发布说明中废弃并返回明确迁移错误；确有外部消费者的入口只保留薄适配层。需要确认的操作不能由适配器自动生成确认令牌，幂等与版本约束也不能放宽。
3. 再收敛前端状态归属：项目快照/版本是一组，编辑选择/面板是一组，生成会话/进度是一组。以场景测试约束切换、输入、取消与重开，避免组件之间互相调用 setter。
4. 最后按上述边界提取画布投影、检查器和会话控制；不把“拆成很多文件”或引入全局状态框架当作完成标准。

本次复核时 `App.tsx` 为 5,992 行，其中 App 主函数约 3,923 行，其余包含检查器与画布投影等代码。这个规模值得治理，但文件长度本身不是性能问题的证据。

## 后续结构重构收尾

按上述顺序继续实施，而非把重命名算作功能完成：

1. 删除 `project-routes.ts` 中 11 个旧写入口的业务实现及重复素材解析辅助函数。原入口只返回 410 和命令迁移地址，不自动转发、确认或放宽权限。完整对照见[迁移说明](canvas-api-migration.md)。
2. 将仓库内调用旧 API 的测试改为显式命令与预览；删除需要测试明确指定确认，复制镜头验证独立对象，而不是保留旧浅引用语义。新增停用路由测试确保快照、版本、审计均不变。
3. 项目快照和版本改为一组文档状态，删除 App 中另外维护的项目 ID、最新版本及快照引用。普通异步响应不能切换项目；显式导航使用请求序号，迟到的导航错误也不覆盖新导航。后台更新不再替用户重新选择已经取消选择的镜头。
4. 提取无写入副作用的画布投影、生成视图模型和检查器；检查器按需加载。保留既有有序生成提交和恢复模块，不再建另一套生成框架。
5. 连线手势与资产库连接共用预览/执行边界。修正前端封装自动取得并附带替换确认令牌的问题；替换须由用户确认原版本，取消不执行，冲突不自动重新批准。删除前端按单个目标候选猜测另一条线的回退。

该阶段 `App.tsx` 从 5,992 行降为 4,111 行；这主要说明投影和检查器已有独立归属，**不等于当时工作区主函数已彻底拆解**。当时剩余编辑选择、表单和部分生成编排仍在 App；这两项的后续关闭结果见下一节。现有首页设计、用户数据、权限、撤销和生成记录未因重构删除。

首屏 JS/CSS 为 776.4 KiB（上一轮 897.6 KiB），总 CSS 259.9 KiB，均未放宽原有预算。500 节点浏览器验收本次记录加载 442 ms、动画帧 P95 19.5 ms；这是当前 Linux 测试环境测量，不代表所有设备性能。

本轮 `pnpm verify` 通过，包含 329 项单元/集成/脚本测试；37 项浏览器测试全部通过。新增验收包括替换连线的取消/确认/撤销，以及 A 项目已提交修改的迟到响应不覆盖已打开的 B 项目；既有输入、媒体、生成恢复、权限与项目同步测试继续保留。Linux x64 包内运行时已经再次验证启动、端口复用、登录与项目默认位置重开保留、自有租约释放；没有发布新安装器，不能据此宣称新版 Mac / Windows 窗口或真实 GPU 生成已验收。

## 选择状态与生成编排：专项关闭

上节记录的两项残余债务已继续处理，当前归属和完成标准见[工作区状态说明](workspace-state.md)。不是把原函数包进一个新文件：

1. 节点、连线、空白、镜头上下文、检查器和右键锚点由同一选择转换维护。删除 App 中独立的 setter、连线身份引用和右键操作对象副本；项目响应接收接口也不再允许指定首选镜头。
2. 草稿按镜头与工作流隔离，连线输入由项目文档推导。删除 App 中在连线后手动补写首尾帧、工作流切换时交叉覆盖偏好的逻辑。
3. 环境发现、草稿和生成会话分别有唯一所有者；App 不再直接提交、取消、轮询任务或发现工作流。新提交与重开的任务统一使用已有运行订阅，删除独立提交轮询及重复传输进度轮询。
4. 明确取消等待提交确认后核对选中镜头的真实 Run，停止尚未发送的候选；导航只解除视图，不擅自停止服务端任务。重试复用实际工作流的参数检查，批次进度按已保存候选计算并消除重试重复计数。
5. 新增状态转换、运行参数来源、取消范围、批次统计和源码边界测试，以及跨工作流草稿、提交中取消、跨镜头取消的浏览器回归。模拟生成响应只证明客户端编排，不作为真实 GPU 生成证据。

`App.tsx` 当前为 3,031 行。保留的页面组合、项目操作 UI 和展示适配不是选择或生成状态的第二份所有者，不再为减少行数增加抽象层。首屏 JS/CSS 为 780.6 KiB，总 CSS 259.9 KiB，未放宽预算。原有测试没有因本次模块提取而删减。

最终验收：`pnpm verify` 通过，341 项单元/集成/脚本测试及 40 项浏览器测试全部通过。最终 500 节点测试记录加载 369 ms、动画帧 P95 16.9 ms。Linux x64 桌面包内运行时再次通过启动、远程 helper 端口复用、登录和默认项目位置重启保留、自有租约释放检查。这些结果不等于已发布安装器，也不覆盖新版 Mac / Windows 原生窗口或真实 GPU 生成质量。

# TakeBoard 实现审查与升级记录

审查日期：2026-08-13

## 本轮已修复

### P0：数据正确性

- 为同一项目的写请求和会回写状态的 Run 轮询增加串行锁，避免生成提交、素材上传、画布移动和候选决策基于旧快照互相覆盖。
- 读取不存在的项目不再创建空目录或 SQLite 文件。
- 项目快照新增 Entity → Asset、Run Input → Domain Object、输入素材哈希和 Active Approval 一致性校验。
- 快照临时文件使用唯一名称，避免同进程并发保存互相覆盖临时文件。

### P1：生成可靠性

- 在上传到 ComfyUI 前验证原生 Recipe 和首尾帧素材，音频、视频或失效 ID 不再被当作图片提交。
- 普通 I2V 不再因为表单残留的尾帧 ID 而额外上传尾帧。
- Wan 帧数统一为 `4n+1`，任意时长/FPS 组合不会产生不兼容帧数。
- ComfyUI 上传、提交、History 和下载增加超时，不再无限挂起 HTTP 请求。
- 结果回收优先且只接受视频输出；Workflow 已完成但只有预览图时明确标记 `NO_VIDEO_OUTPUT`，不再永远显示生成中。
- 媒体接口支持 HTTP Range，长视频可以按需加载和拖动播放。
- Run 参数快照补充负向提示词。

### P1：工作流兼容

- 单个损坏、超时或无法读取的 Workflow 不再让整个目录扫描返回 503；健康工作流继续展示，并返回逐文件 warning。
- Workflow 路径增加边界校验。
- 导入使用唯一文件名，避免同名 JSON 静默覆盖。
- 导入接口返回与目录扫描一致的完整 Workflow Summary。
- ComfyUI 暂时离线时，两个已原生适配的 Wan Recipe 仍有前端安全回退定义。

### P1：创作体验

- 切换项目/镜头会重建正确的首尾帧上下文，不会残留上一项目的素材 ID。
- 上传素材和 Run 轮询不再重置用户正在编辑的提示词。
- 生成轮询使用独立忙碌状态，不再锁住资产库和其他项目操作；切换项目后旧轮询不会覆盖新项目界面。
- 后台 Run 更新不再每三秒强制切回正在生成的镜头。
- Comfy-only Workflow 的动作改为“在 ComfyUI 中打开”，与原生排队能力明确区分。
- 原生生成前显示缺少提示词、首帧、尾帧或非法数值等可操作原因。
- 资产库增加“全部”和未分类图片，显示当前首尾帧选中状态，上传时分类始终明确。
- 移除真实项目中的 Demo 硬编码场景名、类型和时长，改用项目真实数据。

## 自动化覆盖

新增测试覆盖：

- 不支持的 Recipe 不接触 ComfyUI；
- 非图片素材不能作为首帧；
- 无视频输出的已完成任务会失败收敛；
- 媒体 Range 请求；
- 单个损坏 Workflow 的隔离；
- 不存在项目的只读无副作用；
- 同项目并发写请求串行；
- Entity 缺失素材引用；
- Wan `4n+1` 帧数。

## 本轮追加完成（第二轮）

- MiniMax H3 T2V/I2V 已映射为原生 Recipe：T2V 不再强制首帧，支持可选首尾帧、24 fps、Steps、`17n+5` 帧网格和安全分辨率归一化。
- LTX 2.3 I2V 已支持将当前 ComfyUI UI 子图展开为 API Prompt，并注入图片、提示词、尺寸、时长、FPS、Seed 和输出路径。
- 新增 Recipe Contract `0.1`：版本、能力、输入/输出槽、Workflow SHA-256、节点与模型依赖、类型安全绑定。
- 每个原生 Prompt 在入队前读取 `object_info`，检查缺失节点、必填字段和悬空连线；兼容 ComfyUI 动态 `values.*` 输入。
- 部署稳定的 `takeboard_workflow` 深链接桥，可从 TakeBoard 直接在 ComfyUI 载入指定 Workflow；不需要启用 Python 自定义节点或重启推理服务。
- 图片上传增加 PNG/JPEG/WebP 文件签名、MIME 一致性、像素安全上限和真实解码；生成 512px JPEG 代理图并缓存展示。
- 修复 React Flow 覆盖画布顶部按钮的层级问题。
- 真实 Wan 2.2 FLF 1 秒/17 帧 GPU 冒烟测试通过：Run 完成、MP4 回收、Asset 和候选 Take 登记成功。
- 兼容当前 ComfyUI `SaveVideo` 将 MP4 放在 `outputs.images` 的协议差异，同时只接受 `.mp4/.webm`，不会把预览 PNG 误当视频。

## 仍需后续完成

1. 服务器当前没有安装图片生成 checkpoint，因此文生图/图生图已有通用 Recipe Contract 和 Workflow 检测入口，但尚不能在这台 4090 上做真实原生生成；应在确定首个图片模型后增加一套官方 T2I/I2I Recipe，而不是硬编码一个不存在的模型。
2. 当前项目锁只覆盖单个 TakeBoard Server 进程；未来多实例部署需要数据库级乐观并发或分布式锁。
3. LTX 2.3 已通过真实 ComfyUI `object_info` 预检，尚未消耗 GPU 生成完整成片；建议在有明确 LTX 使用场景时补一次质量/耗时基线。
4. 当前 Run 进度以三秒 History 对账为主，尚未接 WebSocket 百分比进度与服务重启后的后台自动恢复。

# TakeBoard 路线图

更新时间：2026-09-10

## 产品目标

让创作者在一张画布中整理素材、连接工作流、生成并比较结果，最终把满意的图片和视频保存在自己掌控的项目目录。

本机创作不以账号、门户、付费模型或多设备调度为前提。复杂能力只有在解决实际需求时才进入主流程。

## 当前边界

- 已发布版本：`v0.2.0-beta.4` 桌面预览；可下载内容以 [Release 和下载指南](downloads.md)为准。
- 当前源码：本机项目可独立连接远程 ComfyUI；连接与传输改动仍需新版安装包验收，见[生成设备与项目位置](generation-and-storage.md)。
- 自定义工作流：依据真实内容、显式参数绑定与依赖校验执行，不承诺任意 JSON 导入即用。
- 可选能力：账号共享、远程项目、Portal、多设备策略、备份和扩展；默认创作流程不要求配置全部能力。
- 成本目前可以记录未知值或按设备费率估算；没有真实云账单 Adapter，不宣传自动省钱或付费升级画质。
- 验证记录见[发布门槛](release-gates.md)与[兼容记录](compatibility-matrix.md)，测试通过不等于所有安装器和模型都已验收。

## 下一步，按用户结果排序

1. **交付一致的桌面体验**：构建新版安装包，验收 Mac / Windows 的文件夹选择、连接切换、退出与重开；不能用源码测试代替安装包验收。
2. **跑通陌生用户的第一条真实生成**：从空白安装到导入自己的工作流、取得本地结果，记录失败原因和必须求助的步骤，再据此调整交互。
3. **守住已完成的状态边界**：旧画布写实现已退休，选择状态与生成编排已从 App 收敛到领域模块，见[完成标准](workspace-state.md)。新交互应沿用这些入口，不重新增加独立 setter 或生成轮询。
4. **改善有证据的瓶颈**：先测量大型项目、长视频和慢网络的实际卡点，再决定是否需要断点续传、媒体代理或存储拆表。

## 暂不作为默认建设目标

- 官方公共 SaaS、强制账号与多租户收费体系。
- BYOK 商业账单、自动选择最便宜模型、自动 Draft → Final 升级。
- 任意代码插件市场、自动安装第三方节点或静默升级。
- 完整非线性剪辑器、Agent 自动创作、分布式任务平台。
- 已停止分发的便携包与第二套 Recipe 协议。

这些不是“永远不做”，但不能因为早期清单里出现过，就被当作成熟产品必须完成的任务。

## 完成标准

每个改变应同时有可操作的用户结果、失败与恢复边界、相应测试及准确文档。
优先删除没有调用者或实际用途的东西；其次收敛重复入口。不得为减代码而删除权限、
原始素材、生成来源、恢复记录或真实性校验。

历史评估保留在[成熟度审计](maturity-audit-2026-08-30.md)和 Git 历史中；本页不再重复早期按天估算的 M0–M2 任务表。

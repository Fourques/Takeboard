# TakeBoard 创作工作站指南

更新时间：2026-08-31

## 这一版解决什么

TakeBoard 现在把“项目管理画布”和“ComfyUI 底层工作流”分成两层：日常创作只暴露提示词、参考素材、分辨率、时长、帧率和种子；需要改节点、模型或采样细节时，仍可进入 ComfyUI 深度编辑。

图片工作流会按能力隐藏无关的视频时长和帧率。Qwen-Image-2512 文生图默认使用官方竖版尺寸与 50 步质量模式；
图生图额外显示重绘强度。生成结果不是临时预览，而会进入当前项目的 Asset、Take 和来源记录，并能继续拖入后续
图生图或图生视频流程。模型文件、质量/快速模式和显存边界见 [Qwen-Image-2512 本地图片生成](qwen-image-2512.md)。

界面提供曜石黑、明亮白和彩色三套主题。主题保存在浏览器本地，项目之间保持一致。顶部的“显示”菜单可独立调整字体与控件到 90%–140%；设置只保存在当前浏览器，不改变画布坐标、素材分辨率或生成尺寸。调整后 TakeBoard 会重新测量画布和侧栏，适合高 DPI 屏、低分辨率设备与远程桌面。

## Workflow 与模型

打开画布右上角的“工作流”即可：

1. 自动扫描当前 ComfyUI `workflows` 目录；
2. 识别文生图、图生图、文生视频、图生视频、首尾帧和参考生成；
3. 展示 JSON 中检测到的模型、节点数量和可调输入；
4. 拖入 Workflow JSON 或 API Prompt JSON，隔离保存到 ComfyUI 的 `workflows/TakeBoard` 并立即进入当前电脑诊断；
5. 为非内置工作流确认 TakeBoard 参数映射和执行信任，验证完成后再选择到镜头，或进入 ComfyUI 修改底层节点。

工作流现在明确分为四种状态：

- **内置适配**：由 TakeBoard 维护和测试的稳定 Recipe；
- **待映射**：只完成导入和管理，尚不能从 TakeBoard 提交；
- **已验证**：用户检查并信任了提示词、尺寸、Seed、时长和素材入口的节点映射，可直接提交；
- **映射失效**：底层 Workflow 内容已改变，SHA-256 与确认时不一致，必须重新检查。

建立映射时，TakeBoard 会读取真实 Workflow，转换普通画布节点和多层子图、去掉注释与 Reroute 等前端节点，并用当前 ComfyUI 的 `/object_info` 校验节点类别和必需输入。自动识别只负责给出候选，最终映射与“信任并启用”必须由用户确认。视频节点使用 `num_frames`、`frame_count` 等帧数输入时，会建议按当前 FPS 换算；高级模式可以明确选择 `秒 × FPS`、`+1` 或 `-1`，不运行任意公式。绑定文件保存在 ComfyUI 用户数据的 `takeboard/bindings`，不会改写原 Workflow。

导入成功不代表安全或兼容性已经验证。工作流可能包含第三方节点、网络或文件操作；只应启用来源可信且自己理解的工作流。无法可靠转换的扩展图仍会停留在待映射状态，可以从 ComfyUI 导出 API Format 后再导入。

需要换电脑或交给团队成员时，实例管理员可以为任一工作流导出 `.takeboard-recipe.tgz`。Recipe 包包含真实 Workflow、当前有效的 Binding（如有）、模型与节点依赖清单、格式版本，以及逐文件 SHA-256；不包含模型文件、Custom Node、账号或主机路径。导入会限制压缩包大小和条目、拒绝路径穿越与额外文件，并逐项核对清单、内容哈希和依赖声明后才以不冲突的新名称写入 `workflows/TakeBoard`。

Recipe 包只传递“映射草案”，不传递执行信任。即使原电脑已经验证过，目标电脑仍会把它标成待映射，重新检查当前 ComfyUI 的节点类别、必需输入和模型，然后要求管理员明确点击“信任此工作流并启用”。这样既保留了复杂参数映射，也不会让外部压缩包绕过第三方节点安全边界。普通 Editor/Viewer 可以查看诊断和使用已验证工作流，但不能导入、导出、归档或启用全局 Recipe。

当前内置 Recipe 覆盖 Qwen Image 文生图/图生图、MiniMax H3 T2V/I2V/Ref2VA、Wan 2.2 I2V/首尾帧和 LTX 2.3 I2V。自定义 JSON 不再依赖文件名决定执行能力；通过映射预检后，TakeBoard 会执行该文件转换得到的真实 API Prompt，而不是替换成同名的硬编码节点图。

## 精简生成参数

不同工作流会按识别结果显示所需输入，而不是把所有 ComfyUI 节点复制到画布：

- 正向/负向提示词；
- 首帧、尾帧或参考资产；
- 宽高、时长、帧率；
- seed，以及后续 Recipe 明确开放的 steps/CFG。

选择“随机 seed”只改变当前表单；每次 Run 仍会保存最终 seed、Recipe、输入资产和参数快照，便于复现。

每轮可以选择生成 1–4 个候选。它们在 ComfyUI 中是相互独立的 Run，各自保存 Seed、Prompt ID、批内序号和状态；一个失败不会撤销其余任务。镜头面板会汇总最近一批的真实状态，失败、取消或失联的成员可以按原输入快照单独重试，重试关系也会保留在 Run 谱系中。停止一批任务时，服务端逐个确认取消和清理，不会只停当前看到的一个。

## 分镜墙与可选整片工具

左侧镜头导航的“分镜墙”入口提供按场次和播放顺序排列的整片视图。顶部同时显示已采用镜头数、待选择镜头、正在生成数量、计划时长与已覆盖时长；卡片优先显示 Approved Take，没有批准结果时显示最近可用候选，没有生成内容时使用轻量占位而不是黑色视频框。

单击卡片在右侧进行只读图片/视频预览，双击或“回到画布查看”返回对应镜头。Editor 和 Owner 可以拖动卡片，或使用可键盘操作的前移/后移按钮调整同一场次内的播放顺序；顺序通过项目命令写入、进入操作记录并可安全撤销，不会移动画布节点或改写 Run。Viewer 可以查看覆盖率和媒体预览，但不会看到排序操作。

分镜墙、顺序调整、覆盖率和单镜头采用属于核心流程。启用“批量审片”扩展后，额外的审片视图会把同一项目的镜头和候选放在一处。先在多个镜头上选择候选，再点击预览；确认层会列出本次决定数量和会替换的现有批准数量。只有确认时项目 revision 仍一致，整批决策才会一次写入。其他成员已经改变项目时，TakeBoard 会拒绝旧预览并要求重新检查，不会悄悄覆盖。

Run 始终保存执行端、成本精度和可用的单次成本，这是复现与调度依据。启用“成本洞察”扩展后，成本卡才会按币种分别汇总。明确金额不代表所有生成都已计价：界面同时显示精确、估算和未知 Run 数。自托管 ComfyUI 节点可在首页执行端面板填写每小时成本，运行结束后按实际墙钟时长形成估算；留空就诚实显示未知。只有未来接入能返回真实账单的 Provider 时，才会记录为精确成本。

## 多执行端与执行策略

首页右上角 ComfyUI 面板同时是执行端管理入口。实例管理员可以添加：

- `https://worker.example.com` 形式的受保护远程 ComfyUI；
- `http://127.0.0.1:8189` 形式的 SSH 隧道本地端口。

不要在 URL 中写账号、密码或 Token。TakeBoard 不接受带 query 的端点，新执行端也不会自动获得图片和视频传输权；确认连接对象可信后，再单独点击“允许素材”。质量定位用于“质量优先”策略，小时费率用于成本估算和预算策略。移除执行端只停止新调度，不会破坏已有 Run 的来源和在途对账。

镜头的高级生成设置提供均衡、仅本机、隐私、最快、成本、质量和预算上限策略。仅本机、隐私和预算是硬约束：没有合格节点就阻止生成。每个生成结果的“执行与成本依据”会显示最终节点、选择原因、其他候选为何被排除，以及成本精度；不需要根据结果猜测是否发生了远程或付费切换。

## 扩展库

项目顶部的“扩展”打开实例扩展库。粗剪预览、成本洞察、批量审片和成片完整性质检是随软件提供但默认关闭的四项扩展：个人创作不需要因此多看一层界面，工作室可以只启用真正需要的能力。成本洞察还会增加未知成本质检；成片完整性质检检查未采用镜头、失败/失联运行和视频元数据。实例管理员也可以导入 `.json` 扩展清单；TakeBoard 先显示权限、功能贡献、警告和内容指纹，确认安装后仍保持停用，需再次启用才生效。

当前扩展只允许启用 TakeBoard 预先实现并声明权限的工作区功能、结构化质检规则和外部工具链接。它不会运行 JavaScript、Python、Shell，也不会替扩展安装 ComfyUI Custom Node。这一限制让团队可以先安全共享规则、入口和试验性功能，而不让一个 JSON 文件获得服务器执行权限。开发格式见[扩展开发与信任模型](extensions.md)。

## 真实进度与安全删除

生成期间，TakeBoard 订阅 ComfyUI WebSocket 的执行事件。采样器等会报告 `value / max` 的节点显示真实步进百分比；模型加载、解码等未提供步进的节点只显示当前节点与“正在执行”，不会用计时器猜测百分比。页面刷新后会用 Run 中保存的 ComfyUI Client ID 重新建立状态跟踪，并以 History 状态兜底。

删除项目时会先检查该项目所有未结束 Run：运行中的任务按 Prompt ID 中断，排队任务只从队列中删除，不会误停其他项目的当前任务。只有 ComfyUI 队列确认这些任务已经停止/结束后，项目才会移入回收区；执行端离线或无法确认时，删除会中止并保留项目。首页出现“回收区”入口后可以一键恢复完整项目；同名目录已经存在时会生成不冲突的新目录名。

视频任务不再设置浏览器端固定超时。长时间生成会持续同步；SSH、Wi-Fi 或服务短暂中断时，画布显示重连状态并继续尝试，不会把网络抖动误报为生成失败。

## 人物、场景与道具资产

打开“资产库”后可按人物、场景、道具分类上传图片，并给资产命名。资产会同时进入项目数据库、媒体目录和画布，不依赖浏览器临时状态。图片卡片可直接设为当前镜头的首帧或尾帧。

后续资产版本、角色多视图、表情/服装变体都应建立在同一 Entity → Asset 引用关系上，不用把每张图复制成互不相关的文件。

## 访问 ComfyUI 编辑器

远程部署只监听服务器回环地址。需要使用 TakeBoard 和 ComfyUI 编辑器时，在 Mac/Linux 客户端执行：

```bash
./scripts/takeboard-tunnel connect your-gpu-host
```

脚本会打开 TakeBoard 的实际本机地址，并把 ComfyUI 转发到 `http://127.0.0.1:48188`。保持终端运行即可持续访问，按 `Ctrl-C` 或关闭终端会自动释放端口。工作流面板中的“进入 ComfyUI 深度编辑”会携带当前 Workflow 路径；不同 ComfyUI 前端对自动载入查询参数的支持可能不同，无法自动载入时从 `TakeBoard` 文件夹选择即可。详见[远程访问指南](remote-access.md)。

## 验证建议

代码构建、类型检查、API 检测和 Workflow 变换单元测试均可离线完成。部署到自己的执行节点后，建议分别用一张非敏感图片跑通文生图、图生图和一种视频 Recipe，并确认 Run、Asset、Take 与来源连线都能在重开项目后恢复。

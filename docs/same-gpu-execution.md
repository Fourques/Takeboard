# 同卡执行池与空闲显存

## 空闲清理

TakeBoard 的正常生成成功、失败和取消收尾现在都会登记空闲清理。
服务端每 15 秒检查一次已登记的执行端：持续空闲约两分钟后，再检查队列，
通过 ComfyUI `/free` 请求卸载模型和释放可回收缓存。检测到运行、排队或离线，
重新计算空闲时间。不对从未登记的端点做全局扫描，不终止原 ComfyUI 服务。

这不是逐模型引用计数：标准 ComfyUI 没有公开各客户端的模型缓存所有权，
队列检查和释放请求也不是原子操作。释放不发送 interrupt，但可能使后续生成重新加载模型。
CUDA 上下文、第三方节点自行持有的张量不保证释放，所以空闲显存不必归零。
请求被接受也不等于显存已经归零。关闭网页不取消任务；关闭服务端时，对已登记的空闲执行端
再请求一次释放，不再等待缓存宽限期。
已有运行服务需正常升级重启才会载入此逻辑；不为部署清理逻辑强停正在使用的服务。

## 服务退出与重开

确认属于本次 TakeBoard 启动的本机服务，退出服务端时检查项目任务、结果收集及 ComfyUI 队列，
全部空闲才停止。切换到其他设备后，也会检查原本机服务是否仍需保留，而不是遗忘它。
外部启动的服务、不可确认的队列和仍在工作的服务不自动停止。

成功启动且能验证所有权后，将恢复意愿与精确服务配置哈希写入项目根的
`.system/comfy-lifecycle.json`。下次打开服务端，在后台重新做资源预检，再恢复同一服务；
配置已变化时不自动启动。主动点击停止会取消下次自动恢复，退出时的空闲停止则保留恢复意愿。
首次打开未配置的设备仍不会自动下载或启动任意 Python 程序。

目前服务所有权可验证的 provider 为 systemd 和由当前进程创建的 process。
launchd / Windows 服务不支持可靠跨实例所有权验证时仍采取只连接、不自动停止的保守行为。
本轮实测为 Linux 服务端，不等于 macOS 原生窗口和 Windows 服务都已验收。

桌面窗口退出或 IPC 断开时，后台仅为已提交任务保留至结果保存完毕，随后退出；
收尾期间不接受新生成，重新打开可接回当前工作区。没有无限保活：状态不可读、任务已中断
或收尾达到 30 分钟上限时结束等待，停止仍可验证归属的本机服务，结果不冒充成功。
启动器收到明确交接确认后不会继续 SIGKILL 后台收集进程；桌面日志写文件，避免窗口退出断开日志管道。
远程或外部服务不自动关闭。若用户强杀所有后台进程或断电，当前代码无法保证执行收尾，
下次启动依靠持久化记录核对结果，不自动重新生成。

连接设置的服务控制提供“释放显存”：绑定点击时的设备、验证项目与执行队列空闲，再请求卸载，
不停止服务。返回“已请求”，并不假称已经释放所有 CUDA 上下文或第三方节点资源。

## 同卡并行（显式启用）

一个 ComfyUI 进程不能仅靠多次提交就变成并行推理。执行池启动 2–4 个独立进程，
共用现有模型目录，分别使用输入、输出、临时和用户目录。默认不启用，也不接管已有 ComfyUI。

在 GPU 服务器设置 `TAKEBOARD_GPU_POOL_CONFIG` 指向以下 JSON 的绝对路径：

```json
{
  "python": "/absolute/path/ComfyUI/env/bin/python",
  "comfyRoot": "/absolute/path/ComfyUI",
  "gpuUuid": "GPU-12345678-1234-1234-1234-123456789abc",
  "gatewayPort": 18200,
  "ports": [18201, 18202],
  "instanceMemoryMiB": 8192,
  "headroomMiB": 2048
}
```

路径、GPU UUID 和预算都是示例，不能直接照搬。Windows 使用 JSON 转义后的绝对路径。
需要已安装依赖的 ComfyUI Python 环境，支持客户端指定 prompt ID 的近期 ComfyUI，
以及支持 per-process memory fraction getter/setter 的 CUDA PyTorch。
此功能不会自动下载模型或自定义节点。先在设置的连接区域明确启动，再选择此执行池。
Mac 可用已有 SSH 连接方式转发服务器的 gatewayPort；无需在 Mac 上跑 NVIDIA 实例。
只监听 loopback，勿将入口直接暴露公网。它不是多租户安全沙箱。

### 预算与安全边界

- 每实例使用 PyTorch native allocator 上限，禁用动态显存和其他 allocator。
- 预算总和加预留量不能超过总显存；派发还检查真实空闲量，并扣除运行实例未来可能增长的占用。
- NVIDIA 遥测不可用、陈旧或存在非受管计算进程时保持排队，不自动停止外部进程。
- 模型所需显存并未被可靠预测。8 GiB 示例并不表示 H3 能在此预算生成；大模型可能不适合单卡并行。
- 原生 allocator 上限不约束所有第三方 CUDA 分配，也不保证 CPU RAM 足够；OOM 会暂停新任务，不自动重试。
- 当前仅适用于可确认进程显存的 NVIDIA/CUDA；Apple MPS、AMD，以及返回 N/A 的 WDDM 环境不能据此并行。

### 取消、恢复与输出

任务先持久化 UUID 和实例归属，再提交。丢失提交响应时保留预算，不重复提交。
取消只作用于目标实例；不能确认提交状态时，只有验证了身份的受管实例才允许停止。
原 ComfyUI 不在此所有权范围。受管实例完成或取消后尝试空闲卸载，以便其他实例获得显存。

完成输出先复制到执行池独立归档，再公布完成并释放实例位置。原始文件同名不会使旧结果串线。
复制失败保留实例位置，暂停派发，修复磁盘或连接后点击“检查并继续”。
已归档输出不依赖实例继续运行；停止实例不删除结果。日志、输入、原始输出和归档暂不自动删除，
需管理服务器存储；不能将此称为完整的存储保留策略。

网关支持 TakeBoard 的提交、队列、历史、输出、素材上传及进度事件转发。
它不是完整的多实例 ComfyUI 编辑器：调试自定义工作流请使用原 ComfyUI，
不要假定原生编辑器的全局历史和输入预览已聚合。

启动回滚、归档恢复与文件归属。不能替代真实 GPU 的双任务并发、峰值显存、吞吐和视频质量验收。

- 两个独立进程同时运行真实 H3 VAE 编码/解码，保存两份隔离图片。
- 运行中定向取消一个任务，另一个成功完成。

- 原 systemd 服务经过启动、退出停止、重开恢复、再次退出停止的真实服务端验收。

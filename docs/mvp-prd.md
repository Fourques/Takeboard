# TakeBoard MVP 产品需求

状态：M0/M1 执行基线
更新时间：2026-08-13

## 1. 产品命题

TakeBoard 是开源、自托管的 AI 影视内容画布。它借鉴 TapNow、LibTV 的“内容留在画布、来源通过连线追溯”体验，但允许用户自带 ComfyUI Workflow、GPU、远程 Worker 和 API Key。

首版不承诺自动成片。它只承诺：

> 一个镜头从参考素材、生成尝试到最终批准的全过程，不再散落在 ComfyUI History、下载目录和人的记忆里。

## 2. 第一用户与核心任务

第一用户是已经使用 ComfyUI 制作叙事视频，并满足以下至少两项的人：

- 有 3 个以上可复用 Workflow JSON；
- 一个项目有 10 个以上镜头；
- 每镜会生成多个候选；
- 同时使用本地 GPU 和云模型；
- 曾经找不到某个成片对应的提示词、参考图或参数。

核心 Job-to-be-Done：

> 当我为一部多镜头作品反复生成素材时，我希望能看到每个结果从哪里来、为什么被选中，并能继续从批准版本向下生产，而不用依赖文件名和记忆。

## 3. 产品结构

### 3.1 四个区域

1. **项目/场景导航**：项目、场景、镜头覆盖率和运行状态；
2. **创作画布**：放置内容、组织来源和派生结果；
3. **上下文操作栏**：对选中节点执行 Recipe、比较、批准、淘汰；
4. **运行抽屉**：队列、进度、错误、Worker 和参数快照。

M0 不加入 Agent 聊天栏。选择节点后出现确定性的 Recipe 表单，先建立可信的输入输出模型。

### 3.2 五类画布节点

| 节点 | 作用 | M0 |
| --- | --- | :---: |
| Text | brief、剧本片段、提示词、导演备注 | 是 |
| Entity | 角色、场景、道具的身份与参考集合 | 是，最简元数据 |
| Media | 上传或生成的图片、视频、音频 | 是，M0 先图像/视频 |
| Shot | 镜头意图、时长、状态和被批准 Take | 是 |
| Take Stack | 同一生成任务的一组候选及人工选择 | 是 |

Run 不是默认画布节点。它是 Take Stack 中可展开的执行记录，避免运行历史淹没内容画布。

### 3.3 三类连线

| 连线 | 含义 | 可否手工修改 |
| --- | --- | --- |
| `reference` | 用户声明某素材将作为某镜头/任务的参考 | 可以 |
| `generated_from` | 某输出实际使用了哪些输入，由 Run 快照产生 | 不可修改，只可隐藏 |
| `approved_for` | 某 Take 被批准进入某 Shot | 通过批准/撤销批准命令改变 |

不要用一条无类型的线同时表达“摆放关系、生成来源和镜头顺序”。

## 4. M0 黄金路径

### 4.1 用户操作

1. 新建项目和场景；
2. 拖入角色参考图，创建一个文字提示；
3. 新建 Shot 卡并填写目标时长、画幅和镜头意图；
4. 多选文字、角色图和 Shot，点击“生成候选”；
5. 选择一个 Recipe，确认输入绑定和候选数量 4；
6. TakeBoard 上传必要输入并向 ComfyUI 提交 4 次 Run；
7. 画布出现 Take Stack，实时显示 queued/running/completed/failed；
8. 用户打开候选对比，淘汰 3 个并批准 1 个；
9. Shot 卡显示 Approved Take；
10. 关闭并重新打开项目，状态完全恢复。

### 4.2 失败路径必须存在

- Worker 离线：生成按钮禁用，并显示检查结果；
- Recipe 缺节点：入队前阻止，列出缺失 `class_type`；
- 某个 Run 失败：其余 Run 继续，允许只重试失败项；
- 输出文件缺失：保留 Run/Take 元数据，标为 `media_missing`；
- 用户删除来源节点：默认只从画布隐藏，不物理删除被 Run 引用的 Asset；
- 应用意外退出：已提交任务可通过 `prompt_id` 和 History 尝试恢复。

## 5. 分阶段范围

### M0：两周技术与体验 Gate

必须有：

- 单场景内容画布；
- Text、Entity、Media、Shot、Take Stack；
- 本地项目保存/恢复；
- 一个本地 ComfyUI Worker；
- 一个图片或视频 Recipe；
- 4 候选批量 Run；
- 对比、淘汰、批准；
- 来源谱系和 40 Run 可靠性测试。

明确没有：远程 Worker、BYOK、成本路由、Agent、分镜墙、粗剪、桌面安装包。

### M1：两周差异化 Gate

- 一个远程 ComfyUI 或一个 BYOK Adapter；
- Local Only 和 Budget Cap；
- 运行前费用/时间估算；
- Local Draft → Paid Final；
- accepted-take cost；
- Secret 不进入项目包。

### M2：四周私测 Alpha

- 多场景与分镜墙；
- Recipe 导入向导和依赖预检；
- 项目打包导入/导出；
- 缩略图、代理媒体和缓存治理；
- 只读粗剪；
- 5 名真实创作者私测；
- 中英文开源文档和演示项目。

## 6. 非功能要求

- 默认只监听 `127.0.0.1`；
- 300 个内容节点的单场景仍能平移、缩放和选择；
- 不自动播放画布内视频，使用 poster/缩略图；
- 所有保存使用事务或临时文件原子替换；
- Run、Take、Approval 不因重新生成而覆盖；
- 项目导出不含 API Key、登录 Token 和绝对用户目录；
- 一个旧项目无法迁移时必须拒绝打开并保留原文件，不能静默损坏。

## 7. MVP 成功指标

### 技术

- 40 Run 正确关联率 ≥95%；
- 项目恢复测试 10/10 通过；
- Recipe 缺失依赖 100% 在入队前发现；
- 核心 E2E 在 Windows/macOS/Linux 至少两类环境通过，M0 可先 macOS + Linux。

### 行为

- 5 名测试用户中至少 4 名不看说明完成“导入→生成→批准”；
- 至少 3 名愿意带自己的 Workflow 或真实镜头回来；
- 用户找到某个 Approved Take 的来源和参数不超过 30 秒；
- 至少 60% 的测试 Shot 使用多候选和批准动作。

Stars、注册数和 Demo 播放量不是 M0/M1 通过指标。

## 8. 体验原则

1. **来源不消失**：派生结果总在来源旁边出现，原素材不被覆盖。
2. **花钱前确认**：涉及现金成本的操作必须展示输入、数量、模型和上限。
3. **失败可恢复**：单个失败不摧毁整个候选组。
4. **隐藏复杂度，不隐藏事实**：默认不显示 ComfyUI 图，但 Run 可展开查看 Workflow hash、输入、参数和日志。
5. **先人工批准，再做 Agent**：Agent 未来也只能在显式权限和预算内创建计划，不能成为首版数据真相源。

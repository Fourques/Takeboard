# TakeBoard 数据与项目目录规范

更新时间：2026-08-14

## 当前模型

TakeBoard 当前采用“单工作区、项目隔离”的本地优先模式。它不是云端多租户系统，也暂不创建用户账户；一个服务实例可以管理多个项目，每个项目都是一个可独立备份和迁移的 `.takeboard` 目录。

```text
TAKEBOARD_DATA_ROOT/
└── my-film.takeboard/
    ├── project.takeboard.json   # 项目标识、版本和基础元数据
    ├── takeboard.db             # 镜头、节点、边、运行和素材索引
    ├── assets/
    │   ├── originals/           # 用户上传的原始素材
    │   └── proxies/             # 缩略图、代理文件（按需生成）
    ├── renders/
    │   └── <shot-id>/<run-id>/  # 已登记进项目的最终生成结果
    ├── runs/                    # 可移植的运行记录扩展目录
    ├── recipes/                 # 项目级工作流配置
    ├── logs/                    # 项目级诊断记录
    ├── exports/                 # 用户主动导出的成片或项目包
    └── trash/                   # 后续可恢复删除使用的回收区
```

## 数据原则

- 项目隔离：上传素材和生成结果只进入当前 `.takeboard` 项目，不与其他项目混放。
- 节点是引用：画布节点引用镜头、人物、场景或素材；从画布删除节点不会删除底层业务数据和原始文件。
- 复制不复制媒体：复制节点只增加引用，不重复占用素材文件空间。
- 运行可追溯：正式结果按 `镜头 / 运行` 分层保存，数据库保留工作流、参数、输入和状态。
- 临时文件可清理：ComfyUI 的任务输入和原始输出属于运行临时数据；完成、失败或取消后，在结果已经导入项目的前提下清理。
- 快照不含密钥：导出的 JSON 快照不应保存 API Key、访问令牌或主机凭据。

## 用户资产如何管理

当前“资产库”是项目资产库，而不是跨项目的用户全局素材库。这更适合个人创作者和可信小团队：项目可完整打包，人物/场景不会在不同作品间意外串用。后续如果增加账户体系，应在现有项目层之上增加用户空间和可显式共享的全局资产库，而不是改变项目内部格式。

当前版本没有账号、租户、权限或配额隔离，因此只能部署在个人设备、可信局域网或带身份认证的反向代理之后，不应直接暴露到公网。

## 备份与迁移

关闭写入或确认没有生成任务正在落盘后，完整复制对应的 `.takeboard` 目录即可备份。恢复时将目录放回 `TAKEBOARD_DATA_ROOT`，TakeBoard 会通过 `project.takeboard.json` 和数据库重新发现项目。不要只备份数据库，否则上传素材和生成结果无法一起恢复。

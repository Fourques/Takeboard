# 创作参数与画布体验核对（2026-09-15）

## 需求边界

这里的并行明确指 **同一台设备、同一块 GPU 上同时执行多个独立生成任务**，不是多设备分发，也不是允许向同一服务连续排队。

## 已实现的改动

- 生成尺寸与时长只在真正的生成参数中设置；移除镜头信息中容易被误认为会控制生成的重复字段。镜头用途放在生成/结果切换之前。
- 画布和右侧面板共用比例预设，显示对应像素，保留手动宽高。自定义绑定工作流不再统一强制取整为 32 的倍数；原生执行器仍应用各自模型的尺寸约束。
- 图片任务不显示时长；视频工作流只有明确暴露时长输入才显示该控件。生成结果优先使用媒体实际尺寸和时长。
- 输入端口按工作流语义显示源图、首帧等；连线标签只在选中连线时出现，避免常驻重复标签覆盖端口信息。
- 整理保持画布分区与相对位置，按卡片尺寸适度对齐，并为重叠节点留出间隔。支持原有预览与撤销。
- 新收集的生成素材使用提交时的镜头名称、媒体类型和生成序号命名；避免同名冲突，不改动旧素材或 ComfyUI 原文件。
- 资产详情使用单一滚动区域，隐藏可视滚动条但保留滚动能力；预览保留完整比例。长标签/信息仍可滚动，不强行截掉内容。
- 生成记录突出模型、提示词、输入和实际参数；参考素材可定位，并使用从 1 开始的人类可读编号。
- 运行中心保留存储，增加实际显存与运行/等待任务数。面板打开时定期读取，缺失信息不作推算。
- 接受任务后先显示等待，依据执行端队列和历史切换到运行；提交完成后可继续编辑并提交，不要求等待上一任务生成结束。

## 单卡并行：尚未实现

### 核对到的限制

当前安装的 ComfyUI `main.py` 只启动一个 `prompt_worker`，该线程从队列取出任务后同步执行。上游代码也采用单个工作流执行线程：

<https://github.com/Comfy-Org/ComfyUI/blob/master/main.py>

同进程的模型管理和取消状态是共享的。不能直接增加执行线程，把相互影响的模型卸载、取消和自定义节点当作已经隔离。空闲显存快照也不能证明采样、VAE 解码等后续阶段仍有足够容量。

### 后续实施边界

1. 同一设备下管理独立 ComfyUI 执行实例；用户仍选择一台设备，不把内部实例伪装成不同设备。需显式启用并配置可启动的运行环境，不能从远程服务 URL 猜测 Python、节点目录或启动权限。
2. 每个实例独立端口、进程所有权、输入/输出/临时目录和任务路由。共享只读模型目录并不等于共享显存中的模型副本；需要把重复模型占用计入预算。
3. 准入按物理 GPU 统一计算，保留安全余量和已接纳任务的峰值预算，避免两个提交同时看见同一份空闲显存。峰值记录需要匹配工作流内容、模型/精度、分辨率、帧数、参考输入及运行环境；换模板或尺寸不能沿用不相干的测量。没有可信工作流峰值信息或设备遥测时继续排队，不猜测可并行。
4. 对显存不足设置有界回退，停止接纳新并行任务；不能中断别的实例，不进行无上限重试。显存快照不是硬隔离或零 OOM 保证。
5. 用真实同卡两任务验收执行时间重叠、取消隔离、输出归属、峰值与吞吐量；不能拿两个模拟端点或两个排队请求作为验收。并行也不保证更快，需比较实际吞吐。

这一轮没有启动第二份 ComfyUI，没有更改正在使用的服务，也没有增加一个无法兑现的“自动并行”开关。

## 校验范围

- `pnpm verify`：通过，包括类型、构建、单元/集成测试及现有发布静态检查。
- 非 GPU 浏览器回归：全量 68 条中 67 条通过；一条仍引用旧连接提示文案，更新断言后在新隔离目录重跑完整生命周期，通过。此前复用测试目录造成的残留项目计数错误不作为产品验收依据；最终使用全新目录测试。
- 资产/分镜抽屉取消整层淡入，避免文字在过渡中被整体透明度稀释；无障碍对比度检查通过。最终前端构建与 lint 再次通过。
- 整理性能抽查：当前机器 500 个部分重叠节点约 121 ms；是本地计算测量，不代表所有硬件的体验保证。
- 生成参数浏览器测试检查真实 UI 到提交载荷的链路；生成接口使用受控替身，不消耗 GPU，不能算作真实模型输出验收。
- 队列集成测试验证单端点等待状态和不同端点的取消隔离；不是单卡并行测试。
- Mac 原生安装包、本轮真实 GPU 出图/出视频、单卡并行尚未验收。

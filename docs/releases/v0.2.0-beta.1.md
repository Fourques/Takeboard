# TakeBoard v0.2.0-beta.1 — Resilience & Portable Preview

This prerelease turns three operational promises into verifiable loops: external recovery, portable startup and real-GPU compatibility evidence.

## What is new

- Optional scheduled full-instance copies to an external disk or mounted NAS.
- Atomic copy publication, SHA-256 comparison, local limits and daily/weekly/monthly retention.
- Per-data-root ownership prevents instances sharing one NAS directory from pruning or drilling one
  another's backups.
- Real isolated restore drills that read the external copy into a local temporary workspace, then
  open the restored identity database and every project.
- A clear administrator status card plus redacted diagnostics and security activity.
- Native Linux, macOS and Windows bundles for x64 and arm64, each with an embedded Node.js runtime.
- Archive extraction plus real local HTTP startup smoke tests, SHA-256 files and GitHub
  build-provenance attestations.
- A reproducible 1440×900 product walkthrough and a manifest that says its Demo candidates are not real model output.
- GPU Gate v2 plus a strict machine-readable compatibility matrix bound to a clean Commit, the
  source Workflow, the executed Prompt and the output-video hash.
- One publishable v2 baseline for MiniMax H3 T2V on RTX 4090 / ComfyUI 0.31.0: 101 seconds,
  automated media integrity passed, visual quality deliberately marked `not_reviewed`.
- Cross-platform durable writes use a write-capable file handle, including on Windows, before a
  backup archive, its metadata, restore report or scheduler state is published.
- Portable packaging uses pnpm's injected-workspace deployment, so a clean runner builds from the
  frozen lockfile without relying on legacy metadata caches.
- Windows portable startup converts resolved native-module paths to `file:` URLs before ESM import,
  including drive-letter paths used by `better-sqlite3` and `sharp`.

## Download and verify

Choose the archive matching your OS and CPU, verify the adjacent SHA-256 file, then optionally verify GitHub provenance:

```bash
gh attestation verify takeboard-*.tar.gz --repo Fourques/Takeboard
```

Extract and run `START-TAKEBOARD.command`, `START-TAKEBOARD.cmd`, or `./start-takeboard.sh`. The launcher binds only to `127.0.0.1`, selects a free port from 48120–48139 and stores projects in `~/TakeBoardData` unless configured otherwise.

The launcher persists an identity inside that data directory. It reopens the matching running
instance, rejects ambiguous process ownership and will not silently attach to another TakeBoard
data root. Source installs should rerun `./scripts/takeboard install` after updating so the systemd
unit receives the same stable identity behavior.

## Honest boundaries

- These are unsigned portable previews, not notarized/signed installers.
- ComfyUI, models and Custom Nodes are not bundled or automatically installed.
- External backup automation is disabled until an administrator chooses an out-of-data-root mounted path.
- Backups are full snapshots. Plan capacity and encrypt media at rest.
- Sharing a mounted backup directory is supported, but every machine still needs exclusive access to
  its own live `TAKEBOARD_DATA_ROOT`; never place the live project directory on concurrently written
  network storage.
- The compatibility matrix does not imply that unlisted combinations fail; it means they lack publishable evidence.

Use this prerelease with a verified backup. Please report portable startup results and real Workflow compatibility through the repository Issue templates.

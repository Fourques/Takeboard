# TakeBoard 易用性与可靠性审计

更新时间：2026-08-29

## 本轮覆盖的完整旅程

本轮按“取得项目 → 首次安装 → 本机启动 → SSH 远程访问 → 创建项目 → 连接 ComfyUI → 导入/绑定 Workflow → 生成与查看真实进度 → 网络重连 → 停止任务 → 删除与恢复项目 → 诊断和维护”检查，而不是只检查单个页面。

已经补齐的关键断点：

- Mac、Windows 双击入口和跨平台中文启动器；
- 依赖、源码与生产构建的新鲜度检测，更新后自动重建；
- 数据目录写入预检、重复启动锁、带实例身份的安全停止和日志轮换；
- SSH 本地端口避让，以及远端 `48120–48139` 实际服务端口自动发现；
- ComfyUI WebSocket 真实节点进度，未提供步进时不伪造百分比；
- 长视频无限时同步与临时网络错误自动重连；
- 删除项目之前按 Prompt 精确停止运行/排队任务，无法确认时保留项目；
- 可视化项目回收区与一键恢复；
- 自定义 Workflow 的显式 Binding、内容哈希、信任和执行前校验；
- 流式项目包导出、隔离导入、逐文件 SHA-256 校验和同项目身份冲突保护；
- 数据库升级前一致性备份，以及迁移失败后的自动回滚；
- 回环监听、Host/Origin 边界、安全响应头与生产构建浏览器验收；
- 移除仓库中的个人机器绝对路径，使部署脚本可由 `HOME`、`COMFY_DIR` 和 `TAKEBOARD_REPO_DIR` 配置。

## 仍应继续建设的产品能力

以下不是本轮可以安全“顺手补上”的小改动，应该作为独立里程碑设计和验收：

1. **定时与增量备份**：完整项目包和升级前回滚已经具备；仍需跨磁盘备份计划、保留策略、增量媒体复制和定期恢复演练。
2. **无需 Node.js 的签名桌面安装包**：macOS notarization、Windows 签名安装器和自动更新，才能真正做到面向完全不懂代码的用户分发。
3. **后台通知与任务中心**：长视频完成、失败、等待资源时的系统通知，以及跨项目统一 Run 队列。
4. **远程身份认证**：已提供账号、设备会话、项目角色和安全审计；面向非可信公众运营前仍需 MFA、邮件恢复、组织/配额和安全运营能力。
5. **可移植 Workflow Binding 包**：把 Workflow、Binding、依赖声明和兼容性结果一起导出，减少换电脑后的重新映射。
6. **存储空间治理**：生成前空间预检、项目占用统计、回收区清理策略和大文件去重。

## 后续验收门槛

- 任意失败都必须告诉用户“发生了什么、数据是否安全、下一步是什么”；
- UI 不得把估算值描述成真实进度，也不得把“请求已发送”描述成“任务已停止”；
- 删除、停止、恢复和升级必须具备幂等性，重复操作不能扩大影响范围；
- 默认只监听回环地址，远程入口继续使用标准 SSH 或带认证的反向代理；
- 跨平台功能至少通过 macOS、Windows、Linux 的路径与端口差异检查后再标记为可用。

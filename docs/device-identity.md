# 生成设备身份与连接状态

## 身份

设备配置以持久化 `workerId` 为主键，项目和任务继续引用这个 ID。SSH 目标、服务名、服务端口是设备的连接配置；每次转发分配的本机端口仅存在内存中，不写作设备身份。

保存设备不要求 ComfyUI 在线。设置先保存并选择设备，再尝试连接；连接失败保留记录和错误，不新建替代设备。编辑已保存 SSH 设备的端口保留 ID，可以在服务离线时完成。切换设备或改地址前仍检查未完成任务，不把旧任务自动转到另一台设备。

显式删除将旧 ID 退役并保留历史；之后重新添加创建新 ID，避免旧任务被错误地交给重建后的设备。这与短暂断线、重启和修改端口不同。

## 默认端口与去重

原实现没有局域网机器发现协议：它在启动时构造默认 ComfyUI 地址，并将这个端口候选与手动 SSH 配置一同展示。端口可用并不能证明发现了一台新电脑。

现在，当用户已选择一个保存的设备，未经用户配置的默认端口候选不再进入设备池和执行调度。用户通过配置或选择明确使用的本机服务会保留。此规则不修改历史任务中的旧 ID。

TakeBoard 自己拥有的隧道地址可准确匹配其所属设备；通过这个地址添加或重连时复用原 ID。对同一 SSH 地址的不同端口，要求编辑原设备，而不是默默新建；同机确实需要多个独立服务时，要指定不同的服务名。

**不能自动推断的情况：**外部工具建立的转发、不同 SSH 别名、不同域名可能指向同一服务器，也可能不是。TakeBoard 当前的 ComfyUI 探测没有取得可验证的持久机器/实例标识，显卡型号、模型清单和响应相同都不能用于合并。当前没有跨任意别名的自动合并能力；已有这类重复记录不会被静默删除，需要用户核对后保留正确连接。

## 状态

配置存在与服务可用分别处理。每个配置可处于未验证、连接中、启动中、已连接、服务未就绪、已断开、恢复中状态。只有确认 SSH 已建立且目标拒绝连接，才报告服务未就绪；普通网络失败不冒充“ComfyUI 已停止”。

当前选中 SSH 设备每 15 秒检查或恢复。隧道仍在但 ComfyUI 已停止也会检查服务健康，不把 SSH 子进程存活等同于服务在线。恢复不创建 Worker，不重新生成任务；页面读取状态并保留同一设备条目。

## 验证范围

- 自动化覆盖离线保存、重复保存、受管理端口归属、离线改端口、临时端口变化、控制端重启、SSH 传输中断恢复、删除后重新添加。
- 真实本地 HTTP 服务启停验证服务端口消失/恢复以及控制端重建后 ID 不变；这不是实际 ComfyUI GPU 生成验收。
- SSH 断线和隧道重建使用可控测试传输；尚未以用户 Mac 和远程 ComfyUI 完成本轮实机验收。
